Failure recovery is out of beta and now runs on iOS as well as web and Android. On every platform it stops after three recoveries in one run, and the temporary steps it generates never edit the test or, on mobile, the replay cache. Set ai.failureRecovery: true in momentic.config.yaml to turn it on.. momentic run --remote-browser-region westus3 (or eastus2 ) runs one invocation on hosted browsers in a specific Browser Fleet region. The flag turns on hosted browsers for that run, fails instead of falling back when the region cannot serve it, and is not available through a private Connector. Ships in the next momentic release. See Regions .. The visual-assertion agent has a new v5 , and it is now the default for new projects and after momentic upgrade . It reads small text and fine positional detail more accurately, with 75% fewer errors than v4 on our visual understanding benchmark at a similar median latency. Visual assertions still use 1x credits. Select it in workspace settings, or set visual-assertion: v5 in momentic.config.yaml with momentic 3.60.0 or later.. Hosted browsers and the knowledge base are generally available. Result classification , triage , and AI test selection have dropped their beta and alpha labels as well. The Explore agent is now marked Legacy in settings; use Mo for autonomous bug finding.. New projects from momentic init and the setup wizard get a documented momentic.config.yaml : every option carries a comment, and hosted browsers ( browser.remoteBrowser ), turbo , and the timeout settings appear as commented-out hints. New web projects also start with parallel: auto , which picks a worker count from your CPU cores and a higher one on hosted browsers. Hosted browsers apply to momentic run ; the editor and the MCP server still use local Chromium.. email.send steps can deliver to an address outside Momentic. Ask Momentic to allowlist the recipient address or domain for your organization; delivery to Momentic-provisioned inboxes is unchanged. See email .. V5 assertions without an explicit effort now route themselves to a fast, medium, or extended effort level based on how much reasoning the check needs, and a locator description the fast tier cannot handle moves up a tier on its own. A step that pins its own effort keeps it.. The step cache survives a rebuild of your application: generated SVG reference ids are normalized before hashing, and a src -style attribute that carries a source file and line number ( Button.tsx:3016 ) is left out of the cached selector, so a new build no longer misses on every step.. ​ . . August 2026 . ​ . . Features . ​ . . Testing . An AI action can now cache a conditional flow. When the agent meets UI that only sometimes appears, such as a cookie banner or an already-signed-in session, it records the branch as If <condition> with the steps to take when the condition holds, so later runs replay the same decision from cache instead of re-running the agent. Existing caches keep replaying unchanged. Requires CLI 3.48.0 or momentic-mobile 1.24.0 to replay a cache that contains a conditional. See the step cache .. Failure recovery can now clear a stale AI action cache. When recovery has to step in because the cached actions no longer reach the goal, it drops the entry so the next run resolves the goal again from scratch instead of replaying the same dead flow. See transient recovery .. New cache: false option on an act step keeps the AI action fully dynamic: Momentic replays nothing from cache and writes nothing to it. Use it for flows whose page content changes between runs, where a cached replay would go stale immediately. Available for web and mobile.. AI action no longer gates success on an auto-generated postcondition. When the agent claims a goal is done, an independent reviewer judges the settled app state, the actions the harness recorded, and your goal, and returns the step to the agent with its reasoning when the outcome is missing. A postcondition you author is still a protected requirement the reviewer must confirm. See the AI action guide .. AI action can now read the page’s accessibility tree, not only a screenshot, when it needs more than a screenshot can show. That covers canvas-rendered UIs and surveying the controls available before the agent gives up.. browser.userAgent: null disables Momentic’s default user agent override so the browser presents its native user agent, which keeps UA-sniffed keybindings in step with the keys Momentic sends. The default is unchanged: browsers still present the fixed desktop Chrome user agent unless you configure otherwise. See browser configuration .. ​ . . Configuration . momentic.config.yaml sets project-wide element check timeouts and typing delays, so a slow CI environment no longer needs a per-step edit: browser.elementCheckTimeoutSeconds , browser.typeDelayMs , and browser.pressDelayMs for web, and emulator.elementCheckTimeoutSeconds and emulator.keyPressDelayMs for mobile. A step that sets its own value always wins.. ​ . . Mobile . Mobile tests now wait for the screen to be ready before locating an element with AI, asking a vision model whether rendering has finished rather than only whether the screen stopped changing. A frozen splash screen and a blank content area are both perfectly still. emulator.smartWaitingTimeoutMs bounds every wait and retry on one interaction, and emulator.waitForStability now means the same thing on both platforms: settle after every step that can change the screen, off by default.. New emulator.jurisdiction ( us , eu , or as ) pins hosted emulators to a jurisdiction. Unlike emulator.region , which is a scheduling preference that falls back to another region when capacity runs out, a jurisdiction is a hard constraint: emulator creation fails rather than crossing the boundary, which is what data-residency requirements need.. installApp now works on iOS as well as Android, on local and hosted devices. The step takes a local path, a URL, or an asset://channel/tag reference to an app you uploaded to Momentic, so one test file can install the same build everywhere. iOS takes a .app bundle or a zipped .app bundle, and a hosted device installs from an asset reference or a public URL. Requires momentic-mobile 1.28.0 .. New emulator.localEmulatorStartTimeout raises the boot budget for local simulators and emulators, now 300s by default. Running Android tests on hosted emulators no longer needs Android Studio, the Android SDK, or adb on your machine. The Android quickstart and app setup cover what is still required for local emulators.. Mobile test settings can point at an asset alias, such as nightly , instead of only an immutable build tag. See hosted test environments .. ​ . . AI . July 2026 . ​ . . Features . ​ . . Testing . New run assertions : plain-English statements you expect to have been true at some point during a run, evaluated after the run finishes against frames sampled from the run’s video. Use them for transient UI such as toasts, spinners, and pop-ups that appear and disappear too quickly for a step-based assertion to catch. Any failed run assertion fails the run, and video recording is enabled automatically for tests that define them. Available for web tests. The CLI needs ffmpeg to sample frames; cloud runs evaluate them on Momentic’s infrastructure.. New fill alias sets an input’s value in a single operation instead of typing it key by key, which is much faster for long values. Use it exactly like type: (for example fill: "{{ env.PASSWORD }}" ) when per-keystroke events don’t matter.. Web selector targets (the css field) now accept XPath expressions as well as CSS selectors. Momentic auto-detects XPath, so an expression such as //button[@type='submit'] works in any web command’s css field. See targets .. ​ . . Editor .
